## 修复雷赛Demo DataGridView 列名 "Name" 冲突报错

- 报错：CS0029 无法将类型"string"隐式转换为"System.Windows.Forms.DataGridViewTextBoxColumn"。
- 根因：在 VS 设计器里把 dgvPoints 的列命名成了 `Name`，设计器生成字段 `private DataGridViewTextBoxColumn Name;`，该字段隐藏（hide）了 Form 从 Control 继承的 `Name` 属性（string）。文件末尾 `this.Name = "Form1";` 就变成给列字段赋字符串 → 报错。这是 WinForms 经典坑：**控件/列不要命名为 Name**（同理还有 Text、Enabled 等与 Control 属性重名的）。
- 修复：Designer.cs 中字段 Name → colName（new、AddRange、属性设置块、字段声明共 4 处），列的 Name 字符串保留 "Name" 不影响 DataPropertyName 绑定。构建 0 错误。
- 教训：以后在设计器里改列名，要么直接在"编辑列"对话框把字段名改成 colXxx，要么接受 VS 用属性名生成字段。

## Name 报错复发的真正病根与彻底修复

- 现象：上一轮只把 Designer.cs 字段 Name 改成 colName，但列的 (Name) 属性字符串仍是 "Name"。用户 20:04 在 VS 设计器保存窗体后，设计器按列属性名重新生成了 `private DataGridViewTextBoxColumn Name;`（还残留 colName 声明）→ CS0029 复发。
- 病根：设计器生成字段名的依据是列的 (Name) 属性，不是 Designer.cs 里手改的字段名。只改字段名 = 治标。
- 彻底修复：`this.colName.Name = "colName"`（列属性名也改），DataPropertyName 保持 "Name" 绑定 JobConfig.Name 不变；删除重复声明。构建 0 错误。
- 用户本轮同步新增了 Form1.cs 的 ClearErr/SetSpead/AxisStateMachine(out) 调用，并在 LS.cs 里自行补全了这些方法。

## 开始作业按任务逐个执行（async/await 串行化）

- 原问题：LS.MoveAbs 是 async void（无法 await，三轴同时动、fire-and-forget），内部还有 while(true) 忙等（await 后回 UI 线程会卡死界面）。
- 修改：MoveAbs 改为 `async Task MoveAbs(axisName, pos)`，去掉 stoptime 参数，用 `dmc_check_done != 0` + `await Task.Delay(10)` 轮询等轴停；Form1.btnStart_Click 里 X/Y/Z 逐个 await，之后 `await Task.Delay((int)item.WaitTime)`（WaitTime=毫秒）再去下一个点。
- 注意：btnStart_Click 事件处理器本身保持 async void（事件签名约定，这是 async void 唯一合法场景）。

## 作业语义澄清：点位内三轴并动，点位间串行

- 用户意图：一个点位内 X/Y/Z 同时出动（不是逐轴走），三轴都到位后停留 WaitTime，再执行下一个点位。
- 实现：三个 MoveAbs 不 await 直接发（并行动），`await Task.WhenAll(tx, ty, tz)` 等全到位，再 `await Task.Delay(WaitTime)`。LS.MoveAbs 的 async Task 轮询实现不变。

## 停止作业实现（CancellationToken 协作式取消）

- 要点：只 Stop 轴不够——WhenAll 看到轴停了会继续跑下一个点位，必须取消作业循环本身。
- 实现：Form1 加 `CancellationTokenSource jobCts`；btnStart 里 new + token 传入 MoveAbs(第三参) 和 Task.Delay；btnStop 里 `jobCts?.Cancel()` + Stop 三轴（取消只退出等待，轴必须 dmc_stop 减速）。MoveAbs 加 `CancellationToken token = default` 参数，轮询循环里 `ThrowIfCancellationRequested` + `Task.Delay(10, token)`。
- btnStart 加防重入（jobCts != null 提示）、catch OperationCanceledException 单独处理（正常中止）、finally 里 Dispose+置 null。构建 0 错误。

## jobCts 移入 LS 类（作业状态由控制层统一管理）

- 用户要求把 Form1 的 CancellationTokenSource jobCts 下沉到 LS。
- LS 新增：`private CancellationTokenSource jobCts` + `IsJobRunning` 属性 + `StartJob()`（new CTS 并返回 token）+ `StopJob()`（Cancel + Stop 三轴）+ `EndJob()`（Dispose 置 null）。
- Form1 变纯调用方：btnStart 用 IsJobRunning 防重入、StartJob 拿 token、finally 里 EndJob；btnStop 一行 LS.Instance.StopJob()。删掉了本地字段和 using System.Threading。
- 模式要点：状态（作业是否在跑）归 LS，流程（点位遍历顺序）归窗体，两者通过 token 桥接。
